# HD2 Music 1.2.7 主体加载失败（可复现，1.2.6 正常）

给对方（模组作者）的最小复现记录。日期 2026-11-28，环境 MDL3 `3.0.0-dev.57`（`game_vm=Lua 5.1 debug=true`）、桥接库 `native_version 0.4.5`、Windows 11。

## 现象

| 版本 | 交付握手 | 游戏内主体 | MDL3 设置入口 | F7 界面 | 对局歌词 | 心跳文件 |
| --- | --- | --- | --- | --- | --- | --- |
| 1.2.6 | 成功 | 20 秒后起来 | 有 | 有 | 有 | 每秒刷新 |
| 1.2.7 | 成功 | 从未出现 | 无 | 无 | 无 | 停在 `0` |

1.2.6 与 1.2.7 用的是**同一份交付实现**，只换部署包：

```
1.2.6  9ba626afa44a3aa3.patch_0        12 287 296 B   .stream 154 907  sha256 0cda0f57…
1.2.7  9ba626afa44a3aa3.patch_0        12 760 768 B   .stream 166 097  sha256 8592e8c5…
```

1.2.7 的 `.stream` 与官方包内文件**逐字节相同**（`HD2 Music 1.2.7 - 正式版.zip` 内层解出的 166 097 B 与交付的一致），并由包内签名清单的 `stream_digest` 命中。

## 已确认的三个环节（1.2.7）

1. **壳写请求**：`%LOCALAPPDATA%\HD2Phone\hd2_music_start.dat` = `b47b8bca95c7b43374b34f41:<epoch>:table: 0x…\n`，60 B，**只写了一次**——说明第一次就握手成功（成功即置 `_7e2`，之后按设计不再重写）。
2. **回显被接受**：`hd2_music_ready.dat` 与请求逐字节相同（60 B）。若不等，`_02e()` 会每秒重写请求，实际没有重写。
3. **载荷可被 `_72b()` 解析**：用壳自己的解码器复算——magic `d5d713be8f498220`、`count=42`、每项 `size_a∈[1,8192]`、`size_b∈[2,16384]`、尾部长度校验 `pos+2+tail == len+1`，全部通过（ACCEPT）。

## 失败点

`_7e2 = true` 之后，`on_update` 继续走

```
_e62() 自检 → _cd1("Y\164PX", {"尖","糖"}, …, font_masks, …) 派生密钥
           → _65e(...) 每帧解 2×64 B → _6b4(...) 解压 → _b15(_db5,'@mods/codex/hd2_music/startup')
```

`font_masks` 里 `["尖"]`、`["糖"]` 两个条目都在，`[5]` 长度分别 82 / 92，满足 `#_9ba >= 16`，所以 `_cd1` 的材料齐全。

这条链上**任何一步失败都只置 `_1d7 = true` 后静默返回**（`_b15` 用 `pcall` 包 `loadstring`，失败即 `return`），磁盘、日志都没有痕迹。这也是为什么现象看起来像“模组没装”。

## MDL3 侧的对照

同一台机器，两次会话，只换部署包：

```
1.2.6 会话  03:17:24 SYS_BATCH_FAILED E_BUDGET
            03:17:25 SYS_BATCH_FAILED E_BUDGET
            03:17:37 SYS_WATCH_READY
            （此后安静，03:18:34 主体起来）

1.2.7 会话  02:45:21 SYS_BATCH_FAILED E_BUDGET
            02:45:25 / 02:45:33 / 02:45:44 / 02:45:55 / 02:45:56 连续 E_BUDGET
            （握手在 02:45:20，之后没有安静下来，主体始终没出现）
```

`E_BUDGET: instruction/time/stop limit`、`SYS_SLICE_RAISED native slice 30 ms for 4 s after E_BUDGET`。1.2.7 会话里预算失败**在握手之后持续发生**，1.2.6 会话里则在握手前后就停了。

## 想请作者确认

1. 1.2.7 是否在 MDL3 `3.0.0-dev.57` 上实测过？1.2.7 的壳比 1.2.6 大 7%，`_cd1`/`_6b4`/`_b15` 都是单帧完成的重活，是否可能撞上 MDL3 的单帧执行预算？
2. `_b15` 与 `_cd1` 的失败能否打一条日志（哪怕写一个标记文件）？现在从外部完全分不清是密钥派生、解压还是 `loadstring` 失败。
3. `_16d()` 这条 `bit`/`bit32` 缺失时的回退路径，1.2.7 是否实测过？如果 MDL3 的 Lua 5.1 没有 `bit`，`_a8a` 的 SHA-256 会走字符串大数实现，单帧开销可能远超 1.2.6。

## 附：可在外部复现的检查脚本
